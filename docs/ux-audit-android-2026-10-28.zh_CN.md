# BugChecking Android UI/UX 设计审计 — 2026-10-28

## 1. 范围与证据

本次为原生 Android 配套 App 的全产品审计，重点覆盖四个主页面、共享外壳、轨迹／收藏／地图流程、编辑页、备份设置、设计 tokens、Android 适配与 Material 3 符合度。当前受众是唯一的产品所有者／开发者本人：熟悉隐藏手势，接受学习成本，并把新奇与可玩性视为产品价值。首次使用转化、面向公众的解释成本和收藏手势的无障碍发现性不作为本阶段评分目标；功能正确性、视觉辨识、地图几何稳定性和数据恢复仍按较高标准审计。

使用的证据：

- PLZ110 真机截图，1216 × 2640、560 dpi，包名 `com.bugchecking.app`，版本 `0.1.0`，设备安装更新时间为 2026-10-28。四个主页面均在浅色模式观察；轨迹与“我”还在深色模式观察。
- 二级流程的真机视觉检查：地点库、场所详情、轨迹地图、添加轨迹、编辑轨迹、添加到清单、添加二维码和编辑二维码。检查只进行导航与截图，没有保存、删除或修改业务数据。
- 真机 1.0× 与 2.0× 字体缩放样本；2.0× 还覆盖了二维码编辑器。取样后已恢复 1.0× 字体和设备原有的定时主题模式。
- 主页面与上述二级页面的无障碍节点树。
- 对 `MainActivity.kt`、`PassportDesign.kt`、`TrackFavoriteUi.kt`、`TrackMapScreen.kt`、`BackupSettings.kt`、Manifest、资源与 Gradle 依赖的源代码审阅。
- 对静态回退色板进行计算对比度检查。图片背景上半透明表面的运行时对比度不冒充实测对比度。
- 产品所有者在 2026-10-28 明确声明的五项约束：两个特色入口必须持续可见；轨迹卡高度固定；地图缩放存在点线错位；默认减少提示文案；隐蔽长按收藏属于有意创意取舍。

未测试：首次安装权限顺序、TalkBack 真机朗读顺序、键盘／Switch Access、平板／折叠屏渲染、地图提供方失败、离线转换、实际执行破坏性备份恢复、需要选择本地图片才能进入的头像裁切，以及编辑器的保存成功／校验失败／键盘弹出等状态。地图点位／轨迹线在多级缩放下的消失与错位由产品所有者复现并报告，本轮未独立录屏复现。已安装 APK 与代码中的主要功能一致，但本次审计不能证明它由当前含未提交修改的工作区精确构建。

## 2. 执行摘要

App 已形成可辨识的个人工具，而不是通用 Compose 模板：城市地图底图、旅程带、柔糖容器、“夜雾”深色表面，以及隐蔽长按收藏共同构成产品性格。地图与地点库虽不是主任务，却是必须持续可见的特色入口；正确调整是降低它们相对“添加”的视觉权重，而不是藏入菜单。当前最重要的新增功能缺陷是地图缩放稳定性：点位与轨迹线由代码在相机停止后清空并重建，产品所有者已复现某些比例下消失或错位。深色内容色泄漏仍是直接可见的高优先级缺陷。轨迹卡固定高度是明确约束，现有单行尾部省略方向正确，不应改为自动换行。首次发现性、解释文案数量和隐藏收藏手势不再作为缺陷；正确方向是修正渲染与层级，不是把个人工具改造成面向大众的教学型产品。

## 3. 必须保留

- 已验收的“动态柔糖”浅色系统和“夜雾”蓝灰深色表面。
- 作为产品识别的居中裁切城市地图背景。
- 日期分组与轨迹卡之间的旅程带关系。
- 轨迹、清单、二维码、我四个主入口。
- 有状态的编辑／导入／裁切使用独立页面；简短确认用 Dialog，上下文选择用 Bottom Sheet。
- 清单分组、组内长按排序以及 TalkBack“上移／下移”动作。
- Android 12+ 动态色与经过设计的静态回退色板。
- 轨迹主页持续可见的地图与地点库入口，以及唯一主操作“添加”。
- 轨迹卡统一高度、地点名单行尾部省略。
- 隐蔽、分级、有反馈的长按收藏交互。
- 少提示、少文字按钮、依靠一致图标与位置形成的个人工具密度。

## 4. 快速收益项

1. 在透明主页面 Scaffold 中显式建立 `onSurface` 内容色，并增加深色截图回归。
2. 只保留“添加”为 FAB；地图与地点库改为持续可见的低强调图标入口，不藏入 overflow。
3. 保证轨迹副信息中的数值与单位不拆分，并在 2.0× 字体下测试全部主页面。
4. 在所有动态／浅色／深色组合满足 4.5:1 前，不要再通过降低收藏卡副文本透明度来弱化层级。
5. 将地图点位和轨迹线迁移到 MapLibre 的 geographic source／layer，并覆盖完整缩放、平移与旋转测试。
6. 让编辑器底部动作栏为可滚动内容预留动态安全区；轨迹卡继续固定单行尾部省略。
