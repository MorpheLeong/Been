# AI Passport 配套 App BLE 协议（v3）

AI Passport 是 BLE 外设，Android App 是中心设备。设备请求轨迹记录或清单打卡；App 获取并在本机保存坐标。位置坐标不回传到设备。

## GATT 服务

扫描以下服务 UUID。设备名为 AI Passport。

| 用途 | UUID | 属性 |
| --- | --- | --- |
| Passport 服务 | 01504941-6E8C-214A-10A9-415000000001 | Primary service |
| 设备指令 | 02504941-6E8C-214A-10A9-415000000001 | 优先 Indicate，兼容 Notify，需认证 |
| App 结果 | 03504941-6E8C-214A-10A9-415000000001 | Write，需认证 |
| App 快照同步 | 04504941-6E8C-214A-10A9-415000000001 | Write，需认证 |

所有多字节整数均为 little-endian。Android App 以 connectedDevice 和 location 前台服务保持连接，并显示系统通知。系统仍可因用户强制停止、重启、权限撤销或厂商省电策略终止进程；这不是绝对保活保证。

## 链路安全与配对

GATT 数据链路强制使用已绑定、已认证的 LE Secure Connections 和 128 位密钥。首次连接时，Passport 屏幕显示随机六位配对码，用户需在 Android 系统配对框中输入相同号码；绑定密钥保存在 NVS，后续连接会恢复加密。App 不再按广播名称猜测设备，扫描与服务校验都要求上表中的准确服务和特征 UUID。

首次使用时，App 直接打开 Android 系统蓝牙设置，由系统完成配对码输入和绑定；
App 不再自行调用 `createBond()` 或用自己的超时器判断系统配对结果。系统显示
AI Passport 已配对后，返回 App 点击“连接设备”。从未强制安全配对的旧固件
升级后，请先在 Android 蓝牙设置中删除旧的 AI Passport 配对记录，再重新配对。
配对被拒绝或绑定记录失效时，不会开放指令通知和 App 写入。BLE 链路加密保护
已绑定手机与 Passport 之间的传输；协议 v3 并未对保存在手机或设备存储中的
二维码原文再做一层应用加密。

## 设备发出的指令

### 轨迹记录请求

4 字节：版本 0x03、操作码 0x01、请求 ID uint16。App 获取当前位置，并以“轨迹记录”为名称在手机本地持久化。成功后回传成功结果；失败时回传失败结果。App 数据库永久保留全部轨迹，除非用户手动删除。Passport 只保存并显示手机当前时区下的当天记录；App 回传的时间与时区用于清理设备端上一天的记录，设备时钟跨过本地 0 点时也执行同一清理。

### 清单打卡请求

为适配默认 ATT MTU，设备按顺序发送 Indicate 分片，并等待手机确认后再发下一帧；
Notify 仅作为旧客户端兼容路径，也必须等待发送完成事件后再继续：

| 字节 | 内容 |
| --- | --- |
| 0 | 版本 0x03 |
| 1 | 分片操作码 0x42 |
| 2 | 操作码：打卡 0x02，撤销打卡 0x03 |
| 3–4 | request_id，uint16 |
| 5–6 | 完整请求负载长度 |
| 7–8 | 当前分片偏移 |
| 9–19 | 最多 11 字节负载 |

完整负载为：目的地 ID 长度 uint8、UTF-8 目的地 ID、名称长度 uint8、UTF-8 名称。ID 最多 36 字节，名称最多 47 字节。分片必须按偏移顺序连续重组。

打卡请求可针对设备当前选择的未完成项。App 使用本地名称，并仅在定位与保存成功后推进清单。撤销打卡仅将项目设回未完成，不删除或修改任何轨迹记录，也不新增轨迹。App 获取定位并成功写入本机数据库后才回成功；权限、定位或存储失败都回失败，设备保持当前地点，等待用户手动重试。请求 ID 与目的地 ID 用于幂等去重。

## App 结果

成功帧 11 字节：版本 0x03、结果操作码 0x81、状态 0x00、对应请求 ID uint16、Unix UTC 秒 uint32、本地 UTC 偏移分钟 int16。

失败帧 6 字节：版本 0x03、操作码 0x81、非零状态、请求 ID uint16、错误码 uint8。

设备只把成功响应中的时间戳和清单项目名称写入本机记录，不接收纬度或经度。只有该成功响应才允许设备推进当前项目。

## App 向设备同步快照

快照包含最多 64 个目的地和最多 10 个二维码；二维码名称最多 48 字节、原文最多 192 字节。三个星标码优先占用设备槽位，其余槽位按清单顺序装入未完成地点二维码，剩余空间再放已完成地点二维码。一个目的地最多绑定一个二维码。App 是排序、星标、完成状态和轮转布局的唯一规则来源。

App 仅在用户点击右上角同步按钮时发送清单、二维码和亮屏设置，并串行等待每帧 GATT
写回执。编辑清单、二维码、个人资料或设置只保存到手机，不自动产生同步流量；
BLE 连接仍保持，以接收 Passport 主动发起的轨迹和打卡请求。

- 开始帧（10 字节）：版本 0x03、操作码 0x10、revision uint16、负载长度 uint16、CRC32 uint32。
- 数据帧：版本 0x03、操作码 0x11、revision uint16、偏移 uint16、数据长度为协商 ATT MTU 减 9；默认 MTU 23 时为 14 字节，MTU 247 时最多 238 字节。
- 提交帧（4 字节）：版本 0x03、操作码 0x12、revision uint16。

Android 在连接后请求 MTU 247，并根据实际协商结果动态分片；请求失败或设备不
支持时回退到默认 14 字节。所有帧仍使用有响应写入、同一时刻最多一个在途写入，
单帧失败最多重试两次，因此扩大 MTU 不改变顺序、确认、CRC 与事务提交语义。
后续 iOS 实现应使用系统报告的最大写入长度计算相同分片，不假定固定 MTU。

负载依次为：目的地数量 uint8；每项包含 ID 长度与 ID、名称长度与名称、完成状态 uint8；二维码数量 uint8；每项包含 ID 长度与 ID、名称长度与名称、原文长度与原文、星标状态 uint8、绑定的目的地 ID 长度与 ID。字符串长度均为 UTF-8 字节数。CRC 使用标准 CRC-32/ISO-HDLC。设备收齐并校验完整快照后才替换并持久化；坏帧或 CRC 错误不替换旧快照。

## 边界

- 精确坐标、二维码完整码库和地图编辑记录只留在手机；设备只缓存当前快照与 10 个二维码原文。
- 配对完成后的 BLE 传输已认证并加密。存储加密、应用层端到端加密和生产级硬件验收仍需分别评审；编译成功不等于完整安全认证。
- 二维码由设备本地生成，当前按最高 Version 10、低纠错级别配置。192 字节上限和屏幕扫描效果仍需用目标屏幕、真实手机扫码器验证。



## 资料与提示音设置

快照尾部追加 UTF-8 昵称（最多 48 字节）、简介（96 字节）、社交账号数量及最多 4 个逐行账号 ID（各 48 字节），最后为提示音量 uint8（0–100，默认 50）。快照协议版本为 3。设备两档字号均覆盖 GB2312 的 6,763 个汉字。

### 头像传输

App 在本地保存用户裁切后的正方形 PNG 原图。只有用户主动同步时，App 才将透明区域铺为 `#101C18`，一次缩放为首页 48×48 头像外框中的 46×46 内容区，并通过快照特征发送 4,232 字节 RGB565 小端数据。头像使用独立帧，不改变已有清单快照格式。

- 开始帧：`03 15 01 2E 2E 88 10 CRC32`；格式 1 表示 RGB565 小端，宽高为 uint8，长度和 CRC 为小端。
- 分片帧：`03 16 OFFSET DATA`；偏移量为 uint16 小端，分片必须连续。
- 提交帧：`03 17`；设备仅在字节数完整且 CRC 正确后持久化并替换头像。
- 清除帧：`03 18`；删除持久化头像并恢复“我”占位。

所有帧均采用带确认写入。传统 ATT MTU 下每片携带 16 字节头像数据，协商 MTU 247 后最多 240 字节。乱序、截断、坏帧或 CRC 错误均不会覆盖原头像。

## 亮屏时长设置与设备操作

向快照特征写入四字节 `03 13 LL HH`，最后两字节为 uint16 小端秒数，有效范围 15–600 秒，默认 60 秒。这是独立设置，不修改快照格式或版本号。设备将值保存到 NVS 的 `passport_trip` 命名空间、`screen_secs` 键后才确认成功；坏帧或保存失败返回 GATT 错误。手机应在快照提交后用带确认写入发送此命令。旧固件可能已接受快照但拒绝设置，客户端必须报告此部分失败。

每次安全连接建立后发送一次八字节时间帧，手动同步末尾也会再次发送：版本 `03`、操作码 `14`、Unix UTC 秒
uint32、小端本地 UTC 偏移分钟 int16。设备收到有效帧后立即更新时间和顶栏，
不依赖一次轨迹或打卡成功。时间帧不写入 NVS，设备重新上电后需再次连接或手动同步。

Android 提供 15/30/60/120/300/600 秒选项，后续 iOS 端应使用同样的命令、范围与确认规则。设备按单调时钟计算物理按键空闲时间，时间刷新和蓝牙事件不会延长期限。关闭背光后蓝牙仍运行，第一次按键手势只唤醒，不执行页面操作；息屏时修改时长不会唤醒。

各页顶栏显示时间、电量和手机连接状态图标，首页头像旁只显示昵称。“刷我的码”短按 OK 显示二维码，长按 OK 打开全部已同步码（最多 10 个，每页 7 项）。上下选择、短按 OK 查看、长按 OK 从详情返回清单，再长按返回首页。
