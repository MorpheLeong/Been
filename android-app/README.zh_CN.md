# BugChecking Android 配套端

这是与本仓库 ESP32-C3 设备固件配套的 BugChecking Android App，使用 Jetpack Compose 和 Material 3。在 Android Studio 中直接打开 `android-app` 目录；工程使用 AGP 9 的内置 Kotlin 支持，并附带固定版本的 Gradle Wrapper。

命令行构建 Debug APK：

```powershell
.\gradlew.bat :app:assembleDebug
```

## 当前功能

- 底栏提供“轨迹”“清单”“二维码”“我”四个主入口；设备蓝牙连接、个人身份和设备设置统一收在“我”。每页顶栏区分未连接、已保存、等待同步、正在同步、已同步和失败重试，不再重复显示第二条全局状态栏；编辑内容先保存在手机，用户确认后再同步到 Passport。紧凑屏幕使用底部导航，中等及以上宽度改用侧边导航。
- 轨迹记录通过手机获取一次定位并将坐标保存在本机；Passport 只收到结果时间戳。一级页右下角提供“地图模式”和“手动添加轨迹”两个浮动操作。实际打卡记录的时间与坐标保持只读；App 手动记录可编辑秒级时间和坐标，修改坐标后会明确显示为“手动坐标”。两类记录共用按日期整理的旅程带与地图。
- 打卡清单显示弹簧动效的完成进度，并分为“待打卡”和“已完成”。长按卡片由 Reorderable 驱动，可跟随手指在当前分组内拖动排序，TalkBack 仍保留明确的上移／下移操作。右下角“+”统一进入“添加到清单”，一个地点、多行文本、表格和文件都会先生成候选预览，确认后才写入。Passport 打卡仍只有在定位与本机保存都成功后才自动推进清单。
- 二维码原文默认只保存在手机，右下角“+”负责新增；二维码可编辑、删除和星标（最多 3 个）。点击卡片会进入手机内的高对比全屏出示页，星标可在卡片上直接切换并与编辑页保持同步。二维码与打卡项目的绑定在编辑界面完成；同步时优先选择星标码和行程关联码。Passport 最多保存 10 张，每条原文最多 192 个 UTF-8 字节。
- BLE 由用户在前台启动的前台服务维持，并显示常驻通知、尝试重连。首次使用从 App 跳转 Android 系统蓝牙设置，在系统中输入 Passport 屏幕显示的六位认证配对码；配对完成后回到 App 连接，后续连接恢复加密绑定。Android 仍可能停止进程或限制后台启动，因此不能保证任何情况下都持续在线。
- 资料设置增加设备亮屏时长（15/30/60/120/300/600 秒，默认 60 秒），本地保存后在快照同步完成后发送。新固件会持久化该设置；旧固件会在快照已同步后报告设置失败。

## 当前限制

- 地点名称候选使用 Android 系统 Geocoder，尚未接入专用 POI 服务；自动打卡坐标以实际打卡结果为准，只有 App 手动建立的轨迹允许修改时间与坐标。
- 配对后的 BLE 传输已认证并加密，但存储中的二维码原文没有额外的应用层加密。投入生产前仍需完成真机验收及存储与安全评审。
- 本地单元测试、Lint 与 Debug 构建已覆盖；BLE 连接稳定性、后台恢复、二维码扫描效果和完整打卡流程仍需连接目标 Passport 真机验收。

与固件共用的 v3 BLE 协议见 `../docs/protocols/passport-companion-ble.zh_CN.md`。
